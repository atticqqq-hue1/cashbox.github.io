2. Назначение Приложения

Приложение предназначено для хранения и организации введённой пользователем информации о:

  • категориях кэшбэка;
  • банках и магазинах;
  • подписках и регулярных платежах;
  • вкладах;
  • кредитах и платежах по ним;
  • долгах между людьми и напоминаниях по ним;
  • пользовательских настройках и уведомлениях.

Приложение не является банком, кредитной организацией, платёжной системой или финансовым консультантом. Расчёты, выполняемые в Приложении, носят справочный и приблизительный характер и могут отличаться от расчётов банков, кредитных организаций и иных поставщиков услуг.

3. Информация, вводимая пользователем

Пользователь может самостоятельно вводить в Приложение:

  • названия банков, магазинов, категорий и подписок;
  • размеры кэшбэка и лимитов;
  • суммы и даты платежей;
  • сведения о вкладах и кредитах;
  • сведения о долгах (кто кому должен, сумма, срок);
  • процентные ставки и сроки;
  • выбранные способы оплаты;
  • другие сведения, необходимые для работы функций Приложения.

Эта информация хранится локально на устройстве пользователя. Разработчик не получает содержимое локальной базы данных и не передаёт его на собственные серверы.

Приложение не запрашивает у пользователя паспортные данные, реквизиты банковских карт, пароли или данные для входа в банковские приложения. В функции учёта долгов пользователь может по своему желанию привязать к записи контакт из адресной книги устройства — при этом имя, изображение и номер телефона выбранного контакта сохраняются локально на устройстве и используются только для отображения долга и подготовки напоминания. Порядок доступа к контактам описан в разделе 16 настоящей Политики. При подключении необязательной функции резервного копирования на Яндекс Диск Приложение получает от Яндекса ограниченные сведения учётной записи пользователя в порядке, описанном в разделе 8 настоящей Политики.

Пользователю не следует вводить в свободные текстовые поля сведения, которые не требуются для работы Приложения.

4. Обработка изображений

Для распознавания категорий кэшбэка пользователь может самостоятельно выбрать изображение или снимок экрана из памяти устройства.

Выбранное изображение обрабатывается средствами устройства и не загружается на серверы Разработчика.

Доступ к изображению предоставляется только после явного выбора файла пользователем через системный интерфейс Android. Приложение не осуществляет постоянное сканирование галереи и не получает доступ к другим изображениям, не выбранным пользователем.

5. Локальное хранение данных

Основные пользовательские данные хранятся во внутреннем хранилище Приложения на устройстве пользователя.

Удаление Приложения обычно приводит к удалению его локальных данных. Некоторые данные могут быть восстановлены операционной системой из резервной копии, если пользователь включил системное резервное копирование Android, либо из облачной резервной копии на Яндекс Диске, если пользователь подключил соответствующую функцию (раздел 8).

Разработчик не имеет удалённого доступа к локальной базе данных пользователя и не может удалённо просматривать, изменять или удалять содержащиеся в ней записи.

Доступность и защищённость локальных данных также зависят от настроек безопасности устройства, версии Android, наличия блокировки экрана и действий пользователя.

6. Системное резервное копирование Android

Приложение может поддерживать стандартные механизмы резервного копирования и переноса данных Android.

Если системное резервное копирование включено, операционная система, производитель устройства или выбранный пользователем облачный сервис может сохранить данные Приложения в резервной копии либо перенести их на другое устройство.

Разработчик не управляет такой резервной копией и не получает к ней доступ. Порядок её обработки определяется настройками устройства и правилами соответствующего поставщика операционной системы или облачного сервиса.

Пользователь может управлять системным резервным копированием в настройках устройства.

7. Экспорт и импорт данных

Приложение позволяет пользователю самостоятельно:

  • сохранить данные Приложения в файл;
  • восстановить данные из ранее созданного файла.

Файл создаётся в месте, выбранном пользователем. Приложение не отправляет этот файл Разработчику.

Файл экспорта может содержать введённую пользователем информацию о кэшбэке, подписках, вкладах, кредитах, долгах и настройках. Такой файл следует хранить как конфиденциальный документ.

После сохранения файла за пределами внутреннего хранилища Приложения его доступность и безопасность зависят от выбранного места хранения, настроек устройства, используемого файлового менеджера и облачного сервиса.

Пользователь самостоятельно определяет место хранения файла, круг лиц, которым он передаётся, и момент его удаления.

Импорт данных из файла может заменить текущие пользовательские данные Приложения. Перед импортом пользователю следует при необходимости создать актуальную резервную копию.

8. Резервное копирование на Яндекс Диск и вход через Яндекс ID

Приложение позволяет по желанию пользователя сохранять резервную копию данных Приложения в облаке — на Яндекс Диске самого пользователя. Функция отключена по умолчанию и начинает работать только после того, как пользователь самостоятельно выполнит вход в свою учётную запись Яндекса.

Вход выполняется через сервис авторизации Яндекс ID. При входе Приложение получает:

  • токен доступа с ограниченными правами — только для работы со служебной папкой Приложения на Яндекс Диске пользователя;
  • ограниченные сведения учётной записи (идентификатор, отображаемое имя или логин, изображение профиля) — исключительно для отображения подключённого аккаунта в интерфейсе Приложения.

Пароль от учётной записи Яндекса Приложению не передаётся и Приложением не запрашивается. Токен доступа хранится на устройстве пользователя и не передаётся Разработчику.

В облачную резервную копию входят введённые пользователем данные Приложения, в том числе:

  • банки, магазины и категории кэшбэка;
  • размеры кэшбэка и лимиты;
  • подписки и регулярные платежи;
  • сведения о вкладах и кредитах;
  • сведения о долгах;
  • пользовательские настройки.

Копия загружается по защищённому соединению в служебную папку Приложения на Яндекс Диске пользователя и хранится в личном облачном хранилище пользователя. Разработчик не имеет доступа к учётной записи пользователя, его Яндекс Диску и содержимому резервной копии и не получает эти данные на собственные серверы.

Если пользователь включил автоматическую синхронизацию, резервная копия может обновляться при изменении данных Приложения.

Обработка данных Яндексом при авторизации через Яндекс ID и хранении файлов на Яндекс Диске осуществляется в соответствии с действующими документами Яндекса, включая его политику конфиденциальности и условия использования соответствующих сервисов.

Пользователь может в любой момент:

  • выйти из учётной записи Яндекса в настройках Приложения;
  • удалить резервную копию средствами Приложения или непосредственно на Яндекс Диске;
  • отозвать выданный Приложению доступ в настройках безопасности Яндекс ID.

9. Уведомления

С разрешения пользователя Приложение может отправлять локальные уведомления о:

  • выборе категорий кэшбэка;
  • предстоящих платежах по подпискам;
  • платежах по кредитам;
  • событиях, связанных со вкладами;
  • сроках возврата долгов;
  • других настроенных пользователем напоминаниях.

Уведомления формируются на устройстве пользователя.

Пользователь может отключить уведомления в настройках Приложения или Android.

Содержание уведомлений может отображаться на заблокированном экране в зависимости от системных настроек устройства.

10. Реклама, предложения партнёров и техническая информация

В Приложении используется рекламная платформа Yandex Mobile Ads, предоставляемая Яндексом.

Встроенный рекламный программный компонент может передавать за пределы устройства техническую информацию, необходимую для загрузки, показа, учёта и защиты рекламы.

В зависимости от версии и настроек рекламного программного обеспечения такая информация может включать:

  • IP-адрес;
  • сведения об устройстве и операционной системе;
  • модель устройства и характеристики экрана;
  • язык и региональные настройки;
  • сведения о мобильной сети и подключении к интернету;
  • версию Приложения;
  • рекламные и иные технические идентификаторы;
  • сведения о рекламных запросах, показах, кликах и взаимодействии с рекламой;
  • диагностическую информацию, необходимую для работы и защиты рекламной платформы.

Разработчик не передаёт рекламной платформе содержимое локальной базы данных Приложения, включая суммы вкладов и кредитов, процентные ставки, названия пользовательских записей, стоимость подписок, даты платежей, сведения о долгах и иные введённые пользователем финансовые сведения.

По умолчанию Приложение не запрашивает разрешение на точное или приблизительное местоположение для целей показа рекламы.

Техническая информация может использоваться для:

  • загрузки и показа рекламы;
  • подбора рекламы;
  • оценки эффективности рекламы;
  • формирования статистики;
  • диагностики ошибок;
  • обеспечения безопасности;
  • выявления недействительного трафика и предотвращения мошенничества.

Передача данных рекламной платформой осуществляется с использованием защищённых соединений в соответствии с её технической документацией.

Порядок обработки информации Яндексом определяется его действующими документами, включая политику конфиденциальности и условия использования рекламной платформы.

Пользователь может ограничить персонализацию рекламы с помощью доступных настроек Android и иных предоставленных платформой механизмов. Ограничение персонализации не обязательно прекращает показ рекламы и передачу минимальных технических данных, необходимых для её загрузки, учёта и защиты.

Приложение также может периодически загружать из интернета публичный файл со списком актуальных предложений банков и партнёров (например, специальных условий по картам и иным продуктам). Такой файл одинаков для всех пользователей, не содержит персональных данных и не связан с содержимым локальной базы пользователя. При нажатии кнопки перехода к предложению Приложение открывает внешний ресурс партнёра в браузере или соответствующем приложении; такой переход может сопровождаться партнёрскими (реферальными) метками, позволяющими партнёру учесть переход. Оформление продукта и его условия определяются соответствующей организацией; Приложение не является стороной этих отношений и не получает данные, вводимые пользователем на стороне партнёра.

Анонимная статистика использования. Для улучшения Приложения может применяться сервис обезличенной аналитики AppMetrica, предоставляемый Яндексом. При включённой статистике за пределы устройства могут передаваться:

  • обезличенные события использования — какие экраны Приложения открываются и как часто;
  • версия Приложения, модель устройства, версия Android и язык;
  • технические идентификаторы установки, назначаемые сервисом аналитики.

В статистику не передаются содержимое локальной базы Приложения (суммы, названия записей, заметки, категории, сведения о долгах и контактах) и иная введённая пользователем информация. Сбор статистики начинается только после согласия пользователя (Приложение предлагает включить его в отдельном окне) и может быть отключён или снова включён пользователем в любой момент в настройках Приложения (раздел «О приложении» → «Использование и диагностика»); после отключения передача обезличенных событий прекращается. Порядок обработки информации Яндексом в рамках сервиса AppMetrica определяется действующими документами Яндекса.

11. Сервисы RuStore и системные сервисы устройства

Приложение распространяется через RuStore и может взаимодействовать с сервисами RuStore для установки, обновления и выполнения иных предусмотренных магазином операций, включая проверку наличия и загрузку обновлений Приложения.

RuStore может обрабатывать технические сведения об устройстве, установленной версии Приложения и выполняемых операциях в соответствии со своими условиями и политикой конфиденциальности.

Системные компоненты Android, производитель устройства и выбранные пользователем облачные сервисы также могут обрабатывать техническую информацию в рамках работы операционной системы, резервного копирования, переноса данных и доставки уведомлений.

Разработчик не управляет самостоятельными действиями этих сервисов, но принимает разумные меры для ограничения состава подключённых компонентов и передаваемых им данных объёмом, необходимым для заявленных целей.

12. Передача информации третьим лицам

Разработчик не продаёт персональные данные пользователей и не передаёт третьим лицам содержимое локальной финансовой базы Приложения.

Техническая информация может обрабатываться поставщиками сторонних сервисов, фактически встроенных в Приложение или используемых операционной системой, в том числе:

  • Яндексом — для работы рекламной платформы и сервиса обезличенной аналитики AppMetrica, а также, по инициативе пользователя, для авторизации через Яндекс ID и хранения резервной копии на Яндекс Диске пользователя;
  • RuStore — для распространения и обновления Приложения;
  • рекламными партнёрами и партнёрскими (CPA) сетями — при переходе пользователя по ссылке предложения на внешний ресурс партнёра;
  • поставщиком операционной системы, производителем устройства или облачного сервиса — для системных функций Android, резервного копирования и переноса данных.

Обработка технической информации осуществляется в соответствии с условиями использования соответствующих сервисов, их политиками конфиденциальности, настройками программных компонентов и применимым законодательством.

13. Цели и правовые основания обработки

Информация обрабатывается в объёме, необходимом для следующих целей:

13.1. Предоставление локальных функций Приложения

Обрабатываемая информация:

введённые пользователем записи, даты, суммы, настройки и иные локальные данные.

Цель:

хранение записей, выполнение расчётов, отображение информации, формирование календаря и напоминаний.

Особенность:

обработка выполняется локально на устройстве пользователя.

Основание:

выполнение действий по запросу пользователя и предоставление выбранных им функций Приложения.

13.2. Обработка выбранных изображений

Обрабатываемая информация:

выбранное пользователем изображение или снимок экрана.

Цель:

распознавание содержащихся на изображении категорий кэшбэка.

Основание:

явное действие пользователя по выбору файла и запуску функции распознавания.

13.3. Учёт долгов и доступ к контактам

Обрабатываемая информация:

введённые пользователем сведения о долге, а также — по выбору пользователя — имя, изображение и номер телефона выбранного контакта из адресной книги устройства.

Цель:

ведение записей о долгах, отображение контакта в карточке долга и подготовка текста напоминания.

Особенность:

контакт считывается только в момент его выбора пользователем; данные хранятся локально; отправку напоминания через стороннее приложение выполняет сам пользователь.

Основание:

выполнение действий по запросу пользователя при использовании выбранной им функции.

13.4. Облачное резервное копирование на Яндекс Диск

Обрабатываемая информация:

токен доступа, ограниченные сведения учётной записи Яндекса (идентификатор, отображаемое имя или логин, изображение профиля), содержимое резервной копии данных Приложения.

Цель:

сохранение резервной копии данных на Яндекс Диске пользователя, восстановление данных и перенос их между устройствами пользователя.

Особенность:

функция включается только по явному действию пользователя; копия хранится в личном облачном хранилище пользователя и недоступна Разработчику.

Основание:

выполнение действий по запросу пользователя при подключении и использовании выбранной им функции.

13.5. Показ и учёт рекламы

Обрабатываемая информация:

технические данные устройства, рекламные идентификаторы, сведения о рекламных запросах, показах и взаимодействии с рекламой.

Цель:

загрузка и показ рекламы, оценка её эффективности, обеспечение безопасности и предотвращение мошенничества.

Основание:

согласие пользователя в случаях, когда оно требуется законодательством или настройками рекламной платформы, а также иные предусмотренные законодательством основания.

13.6. Ответы на обращения и сообщения об ошибках

Обрабатываемая информация:

адрес электронной почты отправителя, содержание обращения и иные сведения, которые пользователь добровольно укажет в письме.

Цель:

рассмотрение обращения и подготовка ответа.

Основание:

обращение пользователя и необходимость его рассмотрения.

Дополнительно при отправке сообщения об ошибке:

при использовании встроенной функции отправки сообщения об ошибке к обращению прикладывается техническая диагностическая информация: версия Приложения, модель устройства, версия Android и журналы технических событий работы Приложения. Такие журналы предназначены для поиска причины сбоя и не содержат сумм, названий записей, категорий, сведений о контактах и иного содержимого локальной базы. Отправка выполняется только по действию пользователя.

13.7. Анонимная статистика использования

Обрабатываемая информация:

обезличенные события использования Приложения (открываемые экраны и частота их открытия), версия Приложения, модель устройства, версия Android, язык, технические идентификаторы установки сервиса аналитики.

Цель:

понимание того, какие функции Приложения используются, диагностика проблем и улучшение Приложения.

Особенность:

статистика не содержит сумм, названий записей, заметок и иного содержимого локальной базы; сбор можно отключить в настройках Приложения (раздел «О приложении» → «Использование и диагностика»).

Основание:

согласие пользователя, выраженное включением сбора статистики, и возможность отозвать его в любой момент.

14. Сроки хранения и удаление данных

Локальные данные хранятся до наступления одного из следующих событий:

  • пользователь удалит соответствующие записи;
  • пользователь очистит данные Приложения в настройках Android;
  • пользователь удалит Приложение;
  • данные будут заменены при импорте файла или восстановлении из облачной резервной копии.

Экспортированные файлы пользователь удаляет самостоятельно.

Облачная резервная копия на Яндекс Диске хранится до её удаления пользователем — средствами Приложения или непосредственно на Яндекс Диске — либо в соответствии с правилами сервиса Яндекс Диск. Токен доступа удаляется с устройства при выходе пользователя из учётной записи в Приложении или при удалении Приложения.

Системные резервные копии хранятся и удаляются по правилам соответствующего поставщика операционной системы или облачного сервиса.

Сроки хранения технических данных рекламной платформой, магазином приложений и другими сторонними сервисами определяются их собственными правилами и применимым законодательством.

Переписка по обращениям пользователей хранится в течение срока, необходимого для рассмотрения обращения, защиты прав и законных интересов Разработчика и исполнения требований законодательства.

16. Разрешения Android

Для работы отдельных функций Приложение может использовать:

  • доступ к интернету — для загрузки рекламы, списка предложений, работы сервисов магазина и, по выбору пользователя, резервного копирования на Яндекс Диск;
  • доступ к состоянию сети;
  • разрешение на отправку уведомлений;
  • разрешение на планирование напоминаний;
  • получение события о перезагрузке устройства для восстановления запланированных уведомлений;
  • доступ к контактам — для необязательного выбора контакта при создании долга; сохраняются имя, изображение и номер телефона только выбранного пользователем контакта;
  • доступ к выбранному пользователем изображению или файлу через системный интерфейс Android.

Предоставленные разрешения можно изменить в настройках устройства. Ограничение разрешений может привести к недоступности отдельных функций.

Доступ к контактам используется только в момент, когда пользователь сам выбирает контакт при создании или редактировании долга; Приложение не ведёт постоянный доступ к адресной книге и не считывает контакты в фоновом режиме. Для отправки напоминания о долге Приложение по действию пользователя открывает выбранное им стороннее приложение (например, мессенджер или приложение для SMS) с заранее подготовленным текстом; отправку сообщения выполняет сам пользователь.

Приложение не запрашивает доступ к журналу звонков, содержимому SMS, микрофону, камере или точному местоположению, если такие функции отсутствуют в фактической версии Приложения.

17. Защита информации

Локальная база данных размещается во внутреннем хранилище Приложения, доступ к которому ограничивается средствами Android.

Токен доступа к Яндекс Диску хранится во внутреннем хранилище Приложения. Передача резервной копии на Яндекс Диск и обмен данными с сервисами Яндекса выполняются с использованием защищённых соединений.

Технические данные рекламной платформы передаются с использованием защищённых соединений в соответствии с документацией используемого программного компонента.

Разработчик ограничивает состав подключённых сторонних сервисов и не передаёт им содержимое локальной финансовой базы Приложения, за исключением загрузки резервной копии на Яндекс Диск самого пользователя по его запросу.

При этом ни один способ хранения или передачи данных не может гарантировать абсолютную безопасность.

Пользователю рекомендуется использовать блокировку экрана, защищать учётную запись устройства и учётную запись Яндекса (в том числе с помощью надёжного пароля и двухфакторной аутентификации), своевременно устанавливать обновления безопасности и не передавать экспортированные файлы посторонним лицам.
